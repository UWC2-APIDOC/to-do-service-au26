# Overview
*Learning basic Markdown is one of the most practical skills you can develop for working within the GitHub ecosystem. Markdown is a lightweight markup language utilizing plain-text formatting syntax that allows authors to generate styled text.*
# Advice for getting started
Start by authoring simple README files to practice syntax. To add visual structure within dense technical explanations, use Markdown to format text with headings or lists.
Beginning a line with a plus sign followed by a space will create a bulleted list:
+ Anise
+ Cardamom
+ Ginger

Enclosing text in a single asterisk (*) will italicize it, while enclosing text in double asterisks (**) will render it in bold:
+ *This is italics.*
+ **This is bold text.**

Be sure to familiarize yourself closely with your team’s repository structure. When reporting bugs, suggesting features, or submitting code changes, Markdown allows you to structure your text with task lists or tables as illustrated below:

- [x] Friday
- [x] Saturday
- [ ] Sunday

| Q3  | Q4 |
| ------------- | ------------- |
| July  | October  |
| August  | November  |
| September  | December  |

# Additional Considerations
It helps to understand the unique pros and cons of Markdown:
## Advantages of Markdown 
+ Markdown documents are written in plain text and you can format text using simple keyboard symbols instead of clicking toolbar buttons.
+ It is simple to create, edit and manage Markdown documents with text editors that are used for writing code. For instance, the free and extensible source-code editor Visual Studio Code (VS Code) recognizes Markdown syntax. VS Code includes an option to toggle a preview pane for a Markdown document as you edit.
## Limitations of Markdown
+ You cannot create complex page designs, such as multi-column side-by-side text or custom margins for printing.
+ Creating tables requires manually typing out pipes and dashes, which can become tedious and messy.
